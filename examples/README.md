# Примеры TeamStorm API

**Русский** | [English](README.en.md)

Этот каталог **не является устанавливаемым пакетом**. Он доступен в Git checkout,
но после `pip install .` ничего из `examples/` импортировать нельзя: каталог
существует как готовая к запуску демонстрация работы с API-обёртками.

## Предварительные требования

Скриптам-примерам нужны `pandas`/`openpyxl` (чтение Excel/CSV) и
`python-dotenv` (загрузка `.env`) — вдобавок к собственным зависимостям API-обёрток
`requests`/`pydantic`. Установите дополнение `examples` из склонированного
репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[examples]"

cp .env.template .env
# затем откройте .env и заполните BASE_URL / API_TOKEN
```

В `API_TOKEN` кладётся сам токен: префикс `PrivateToken ` в заголовок
`Authorization` API-обёртка добавляет самостоятельно, поэтому в значении его быть не
должно.

`.env` читается через `python-dotenv`; оба скрипта ниже принимают флаги
`--base-url`/`--token`, если использовать файл `.env` не хочется.

## Что здесь есть

- **`quickstart.py`** — готовая к запуску версия примера из раздела «Быстрый
  старт» в корневом README; параметры подключения берутся из окружения.
  Подробнее ниже.
- **`import_toolkit/`** — приложение-пример, целиком построенное на публичных
  API-обёртках `teamstorm`, с двумя точками входа:
  - `import_toolkit/import_agile.py` — импортирует спринты и задачи в рабочее
    пространство TeamStorm из файла Excel или каталога с CSV.
  - `import_toolkit/sync_uniselect_options.py` — синхронизирует варианты
    значений атрибутов `UniSelect` из эталонного рабочего пространства в одно
    или несколько целевых.
- **`data/`** — примеры входных файлов для `import_agile.py` (см. «Формат
  примеров данных» ниже).

Оба скрипта запускаются напрямую через `python`, они не устанавливаются как
консольные команды:

```bash
python examples/import_toolkit/import_agile.py --help
python examples/import_toolkit/sync_uniselect_options.py --help
```

## `quickstart.py`

```bash
export BASE_URL="https://your-cwm-host"
export API_TOKEN="YOUR_API_TOKEN"
export WORKSPACE_KEY="YOUR_WORKSPACE_KEY"
python examples/quickstart.py
```

Скрипт печатает имя рабочего пространства, затем перечисляет настроенные в нём
типы рабочих элементов и сообщает, сколько рабочих элементов в нём сейчас
есть. Если не задана хотя бы одна из трёх переменных окружения или если вызов
API завершается ошибкой, скрипт печатает понятное сообщение и завершается с
кодом 1 — без traceback.

## `import_agile.py`

Импортирует спринты и задачи в CWM Public API из файла Excel или каталога с
CSV. Флаги (из `import_toolkit/workflows/imports/cli.py`):

| Флаг | Описание |
|---|---|
| `--base-url` | Базовый URL API CWM. По умолчанию — `BASE_URL` из окружения/`.env`. |
| `--token` | Токен API. По умолчанию — `API_TOKEN` из окружения/`.env`. |
| `--workspace-key` | **Обязательный.** Ключ рабочего пространства, в которое выполняется импорт. |
| `--folder-name` | **Обязательный.** Имя корневой папки импорта внутри рабочего пространства. |
| `--input-path` | Путь к файлу `.xlsx`/`.xls` либо к каталогу с CSV-файлами. Фактически обязателен: без него (и без `--excel-path`) запуск завершается с кодом 2. |
| `--excel-path` | Устаревший синоним `--input-path`; пока принимается, но будет удалён. Если заданы оба, используется `--input-path`, а в лог пишется предупреждение. |
| `--dry-run` | Проверяет входные данные и записывает в лог планируемые действия; в API ничего не пишет. |
| `--update-settings` | Разрешает создавать недостающие настройки рабочего пространства (атрибуты, типы), нужные для импорта. |
| `--sync-members` | Добавляет найденных во входных данных пользователей в рабочее пространство и пытается назначить им системную роль `User`. |
| `--allow-insecure` | Разрешает `--base-url` без HTTPS (только для локальной/тестовой среды — никогда с настоящим токеном). |
| `--log-file` | Путь к файлу лога. По умолчанию — `./logs/import_agile.log`. |

### Примеры запуска

Если `BASE_URL` и `API_TOKEN` уже заданы в `.env`:

```bash
python examples/import_toolkit/import_agile.py \
  --workspace-key "YOUR_WORKSPACE_KEY" \
  --folder-name "YOUR_FOLDER" \
  --input-path "examples/data/example_agile.xlsx"
```

То же самое, но с явной передачей URL и токена:

```bash
python examples/import_toolkit/import_agile.py \
  --base-url "$BASE_URL" \
  --token "$API_TOKEN" \
  --workspace-key "YOUR_WORKSPACE_KEY" \
  --folder-name "YOUR_FOLDER" \
  --input-path "examples/data/example_agile.xlsx"
```

Пробный прогон (в API ничего не записывается):

```bash
python examples/import_toolkit/import_agile.py \
  --workspace-key "YOUR_WORKSPACE_KEY" \
  --folder-name "YOUR_FOLDER" \
  --input-path "examples/data/example_agile.xlsx" \
  --dry-run
```

С автоматическим созданием недостающих атрибутов и типов:

```bash
python examples/import_toolkit/import_agile.py \
  --workspace-key "YOUR_WORKSPACE_KEY" \
  --folder-name "YOUR_FOLDER" \
  --input-path "examples/data/example_agile.xlsx" \
  --update-settings
```

Дополнительно с синхронизацией участников:

```bash
python examples/import_toolkit/import_agile.py \
  --workspace-key "YOUR_WORKSPACE_KEY" \
  --folder-name "YOUR_FOLDER" \
  --input-path "examples/data/example_agile.xlsx" \
  --update-settings \
  --sync-members
```

Каталог с CSV вместо файла Excel:

```bash
python examples/import_toolkit/import_agile.py \
  --workspace-key "YOUR_WORKSPACE_KEY" \
  --folder-name "YOUR_FOLDER" \
  --input-path "./agile_csv"
```

### Что делает `--update-settings`

- Создаёт недостающие пользовательские атрибуты, найденные в колонках листа
  `tasks`.
- Создаёт недостающие типы рабочих элементов, найденные в колонке `type`.
- Привязывает созданные (или уже существующие) атрибуты к нужным типам.
- Для атрибутов `UniSelect`/`Tag` может автоматически создавать недостающие
  варианты значений прямо при импорте.

Синхронизацию статусов, рабочих процессов и ролей из внешнего источника флаг
пока **не** выполняет — эти шаги только отмечаются в логе как `skipped`. Без
`--update-settings` недостающие атрибуты и типы не создаются: импорт
продолжается, но пишет предупреждения, а соответствующие поля могут быть
пропущены.

### Что делает `--sync-members`

Собирает пользователей из колонки `assignee_username` и из всех
пользовательских атрибутов типа `User`, находит каждого по идентификатору,
добавляет найденных в рабочее пространство и назначает системную роль `User`,
если она есть в этом пространстве. Без этого флага состав участников не
меняется.

### Коды возврата

- `0` — импорт завершён; отдельные несработавшие обновления `UniSelect`/`Tag`
  по строкам, если они были, считаются некритичными.
- `1` — импорт выполнен, но одна или несколько строк завершились ошибкой; все
  ошибки перечислены в итоговом отчёте в логе.
- `2` — критическая ошибка до начала записи: не указан путь к входным данным,
  файл нечитаем или не прошёл валидацию, отсутствуют обязательные колонки,
  либо не удалось найти рабочее пространство или корневую папку.

### Формат примеров данных

В `data/example_agile.xlsx` два листа:

- **`sprints`**: `sprint_name`, `start_date`, `end_date`.
- **`tasks`**: `name`, `description`, `start_date`, `end_date`,
  `assignee_username`, `sprint_name`, `type`, `Parent`, а также колонки
  пользовательских атрибутов вида `attribute_name[AttributeType]` — например,
  `comment[UniString]`, `estimate[Number]`, `target_date[Date]`,
  `severity[UniSelect]`, `tags[Tag]`, `reviewer[User]`, `spent[TimeDuration]`.

Имена колонок сопоставляются без учёта регистра и небуквенно-цифровых
символов, поэтому `Assignee Username` и `assignee_username` — это одна и та же
колонка. Любая колонка листа `tasks`, не входящая в перечисленные выше,
считается пользовательским атрибутом. Маркер `[AttributeType]` необязателен и
допускает несколько написаний (`string`/`text`, `number`/`int`/`float`,
`date`, `select`, `tag`, `user`, `time`/`duration` и т. п.); колонка без
маркера или с нераспознанным маркером импортируется как `UniString`.

В `data/example_tasks.xlsx` только один лист `tasks` с тем же набором колонок и
без листа `sprints` — удобно, когда `--input-path` указывает на импорт задач
без планирования спринтов.

Поддерживаются и `.xlsx`, и `.xls`, а также старое соглашение о порядке листов
(первый лист — спринты, второй — задачи, независимо от их имён). Для каталога с
CSV файл `tasks.csv` обязателен, а `sprints.csv` — нет.

**Колонка `Parent`**: пустое значение означает, что строка создаётся прямо в
папке `--folder-name`; значение, совпадающее с `name` другой задачи из этого же
импорта, делает строку дочерней для той задачи; любое другое значение
трактуется как имя подпапки внутри `--folder-name` (она будет найдена или
создана автоматически). Непустой `Parent` задаёт текущий родительский контекст
для следующих строк — пока пустой `Parent` не вернёт его к корневой папке.

**Колонка `sprint_name`** (необязательная): если она пуста или отсутствует,
задача не привязывается к спринту. Если в ней указан спринт, которого нет на
листе/в файле `sprints`, спринт создаётся автоматически на интервале
`min(start_date)..max(end_date)` по ссылающимся на него задачам. Значения
`backlog`/`backlog data` (без учёта регистра) привязывают задачу к спринту
бэклога расширения Agile. Если данных о спринтах нет вовсе, вся связанная со
спринтами подготовка пропускается.

## `sync_uniselect_options.py`

Синхронизирует **варианты значений атрибутов UniSelect** из эталонного рабочего
пространства в одно или несколько целевых. Для каждого атрибута, указанного
через `--attribute-name`, скрипт читает атрибут из эталонного пространства,
убеждается, что такой же атрибут есть в каждом целевом, и приводит набор
вариантов в целевом пространстве в точное соответствие с эталоном: недостающие
варианты создаются, варианты с совпадающим нормализованным именем (`trim` +
`casefold`) переименовываются к эталонному написанию, а лишние — те, которых в
эталоне нет, — удаляются.

Поддерживаются только атрибуты `UniSelect`, а перечень атрибутов задаётся явным
списком — режима «синхронизировать всё» нет. По умолчанию скрипт работает в
режиме пробного прогона; реальная запись выполняется только с `--apply`.
Целевое пространство, ключ которого совпадает с эталонным, пропускается. Если
одно из целевых пространств завершается ошибкой, остальные всё равно
обрабатываются, а процесс завершается с ненулевым кодом.

Флаги (из `import_toolkit/workflows/sync/uniselect_options.py`):

| Флаг | Описание |
|---|---|
| `--base-url` | Базовый URL API CWM. По умолчанию — `BASE_URL` из окружения/`.env`. |
| `--token` | Токен API. По умолчанию — `API_TOKEN` из окружения/`.env`. |
| `--master-workspace-key` | **Обязательный.** Рабочее пространство, из которого копируются варианты. |
| `--target-workspace-key` | **Повторяемый.** Одно или несколько рабочих пространств, в которые копируются варианты; хотя бы одно обязательно (проверяется при старте, код возврата 2). |
| `--attribute-name` | **Повторяемый.** Одно или несколько имён атрибутов `UniSelect` для синхронизации; хотя бы одно обязательно (проверяется при старте, код возврата 2). |
| `--apply` | Применяет изменения. Без него скрипт только сообщает, что он сделал бы. |
| `--allow-insecure` | Разрешает `--base-url` без HTTPS (только для локальной/тестовой среды — никогда с настоящим токеном). |
| `--log-file` | Путь к файлу лога. По умолчанию — `./logs/sync_uniselect_options.log`. |

### Примеры запуска

Пробный прогон:

```bash
python examples/import_toolkit/sync_uniselect_options.py \
  --master-workspace-key MASTER_WS \
  --target-workspace-key TEAM_A \
  --target-workspace-key TEAM_B \
  --attribute-name Severity \
  --attribute-name Priority
```

Применение изменений:

```bash
python examples/import_toolkit/sync_uniselect_options.py \
  --master-workspace-key MASTER_WS \
  --target-workspace-key TEAM_A \
  --target-workspace-key TEAM_B \
  --attribute-name Severity \
  --attribute-name Priority \
  --apply
```

Передача учётных данных явно, без `.env`:

```bash
python examples/import_toolkit/sync_uniselect_options.py \
  --base-url "$BASE_URL" \
  --token "$API_TOKEN" \
  --master-workspace-key MASTER_WS \
  --target-workspace-key TEAM_A \
  --attribute-name Severity \
  --apply
```

### Рекомендуемый порядок работы

1. Сначала выполните пробный прогон и просмотрите в логе план создания,
   переименования и удаления.
2. Убедившись, что план верный, повторите запуск с `--apply`.
3. Для первого внедрения ограничьтесь коротким списком `--attribute-name`.

### Коды возврата

- `0` — успех, ни одно целевое пространство не завершилось ошибкой.
- `1` — работа завершена, но в одном или нескольких целевых пространствах были
  ошибки.
- `2` — некорректные входные данные или конфигурация, либо критическая ошибка
  при старте или чтении эталонного пространства.

### Типичные сценарии ошибок

- В эталонном рабочем пространстве нет атрибута `UniSelect` с одним из
  запрошенных имён (атрибут другого типа с таким именем не подходит).
- `--attribute-name` передан дважды для имён, которые нормализуются одинаково
  (код возврата 2).
- Дублирующиеся нормализованные имена вариантов в эталонном или целевом
  пространстве (например, `"High"` и `" high "`) — такой атрибут отмечается как
  неуспешный.
- Дублирующиеся нормализованные имена атрибутов `UniSelect` внутри целевого
  пространства — оно целиком пропускается как неуспешное.
- Ошибки API, сети или прав доступа для одного конкретного целевого
  пространства — обработка остальных продолжается, а сбой отражается в итоговом
  отчёте.

## Переменные окружения

Оба скрипта и `quickstart.py` читают одни и те же три переменные (из `.env` или
из настоящего окружения):

| Переменная | Назначение |
|---|---|
| `BASE_URL` | Значение по умолчанию для `--base-url` — URL экземпляра CWM. |
| `API_TOKEN` | Значение по умолчанию для `--token` — токен API. |
| `WORKSPACE_KEY` | Только для `quickstart.py` — рабочее пространство, к которому он обращается. |

См. `.env.template` в корне репозитория.
